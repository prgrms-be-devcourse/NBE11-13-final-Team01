# 추천 알고리즘 — 입력값과 사용 여부

추천(안서호)이 실제로 읽는 데이터와 쓰는 방식을 적는다. 온보딩 입력·문구, 결과 검증의 기준점이다.
설계 기준(C1~C5)과 결정 기록, 숫자별 출처(근거 표)는 Claude Docs "추천 알고리즘 현황과 개선안"에 있다.

갱신: 2026-10-16

## 1. 사용자 입력값

### 기본 정보 `user_profiles`

| 필드 | 필수 | 추천에서 쓰는 곳 | 비고 |
| --- | --- | --- | --- |
| `birth_date` | 필수 | 연령 조건 (행복주택 청년·청년 매입임대 만 19~39세) | |
| `married` | 필수 | 미혼 전용 계층 판정. 청년 매입임대는 기혼이면 탈락, 행복주택은 기혼이면 '신혼부부 계층 확인 필요' | 온보딩에서 예/아니오를 명시적으로 고른다 |
| `household_size` | 필수 | 소득 기준(도시근로자 가구원 수별 월평균소득 × 비율), 최저주거기준 면적 비교 | |
| `homeless` | 필수 | 무주택 조건 (거의 모든 유형) | 명시적 선택 |
| `monthly_income` | 선택 | 소득 기준. 비우면 '확인 필요' | 만 원, 세전 |
| `total_assets` | 선택 | 총자산 기준. 비우면 '확인 필요' | 만 원 |
| `car_value` | 선택 | 자동차가액 기준. 비우면 '확인 필요' | 만 원 |
| `student_status` | 선택 | 청년 매입임대: 연령 밖이어도 대학생·취업준비생이면 대상 | `NONE` / `UNIVERSITY` / `JOB_SEEKER` |

**삭제한 필드와 이유**
- `job`(직업 자유 입력): 어떤 판정에도 쓰이지 않았다.
- `student`(boolean): 대학생과 취업준비생을 구분해야 해서 `student_status`로 바꿨다.
- `subscription_months`, `subscription_payments`(청약저축): 순위·가점 정보가 수집 데이터에 없어 판정할 수 없다. 온보딩 문구가 "순위 확인에 쓰인다"고 되어 있었지만 실제로는 쓰지 않았다. 공고에서 순위 조건을 구조화해 얻게 되면 다시 넣는다.

**받지 않기로 한 값과 이유**
- 수급자·차상위·한부모·주거급여: 1순위 판정에 필요하지만, 공고 데이터에서 계층별 조건을 구조화해 얻을 수 없어 입력받아도 비교할 대상이 없다. 영구임대 등은 '공고문 확인 필요'로 둔다.
- 혼인일·자녀 수: 행복주택 신혼부부 계층(혼인 7년 이내 또는 만 6세 이하 자녀) 판정에 필요하다. 지금은 기혼이면 '확인 필요'로 두고, 계층 분리를 할 때 함께 추가한다.
- 부모 소득·자산: 청년 매입임대 2순위 판정에 필요하다. 지금은 3순위 기준을 넘으면 "2순위 가능성 확인 필요"로 둔다.

### 희망 주거조건 `user_preferences`

| 필드 | 필수 | 추천에서 쓰는 곳 |
| --- | --- | --- |
| `regions` (JSON, 최대 3) | 필수 | 지역 점수(1순위 1.0 / 2순위 0.8 / 3순위 0.6). 기본 '꼭' 조건이라 관심 지역 밖은 제외. 값은 `"시도 시군구"` |
| `monthly_budget` | 선택 | 비용 점수의 예산 |
| `deposit_max`, `rent_max` | 선택 | 월 예산이 없을 때 예산 = 월세 상한 + 보증금 상한 × 이율 ÷ 12 |
| `area_min`, `area_max` | 선택 | 면적 점수. 둘 다 없으면 면적 점수 제외 |
| `rooms_min` | 선택 | 방 수 점수. 없으면 제외 |
| `housing_types` (JSON) | 선택 | 주택 유형 점수. 없으면 제외 |
| `rental_types` (JSON) | 선택 | **점수에 쓰지 않는다.** 화면 필터 기본값으로만 쓴다 |

**삭제한 필드:** `deposit_min`, `rent_min` — 점수에 쓰이지 않았다. 화면 필터(`HouseFilter`)에는 최소값이 남아 있어 목록을 좁힐 때는 쓸 수 있다.

### 추천 기준 `recommendation_profiles` (사용자당 최대 3개)

| 필드 | 내용 |
| --- | --- |
| `weights` (JSON) | 항목별 우선순위 1~5. 기본 3 |
| `rules` (JSON) | 항목별 `MUST` / `PREFER`. 설정하지 않으면 `region`만 `MUST` |
| `infra_weights` (JSON) | 카카오 카테고리별 가중치 1~5 |

## 2. 공고·주택 데이터 (팀원 수집 테이블, 읽기만 한다)

| 테이블 | 컬럼 | 추천에서 쓰는 곳 | 실데이터 채움률 (2026-10-16, 579주택·1,507호실) |
| --- | --- | --- | --- |
| `notice` | `notice_type`, `title` | 공공임대 유형 분류 (`RentalType.classify`: 유형이 비면 제목으로) | 유형 91%, 제목 100% |
| `notice` | `status` | 모집 상태 필터 (`UPCOMING`·`OPEN` = 모집 중) | 100% |
| `notice` | `apply_end_at` | 마감 임박순 정렬, D-day | |
| `notice` | `detail_url`, `agency_id` | 화면 표시 | |
| `housing` | `province_name`, `district_name` | 지역 점수·필터 (`"시도 시군구"`) | 100% |
| `housing` | `latitude`, `longitude` | 인프라 점수 (좌표가 있어야 주변 시설 조회 가능) | **0%** |
| `housing` | `build_year` | 노후도 점수 | **0%** |
| `housing` | `name`, `address` | 화면 표시 | |
| `housing_supply` | `rent_deposit`, `monthly_rent` | 비용 점수 (원 → 만 원). 둘 다 없으면 '정보 부족' 묶음 | 보증금 54%, 월세 7% |
| `housing_supply` | `exclusive_area` | 면적 점수 | 90% |
| `housing_supply` | `room_count` | 방 수 점수 | 91% |
| `housing_supply` | `housing_type` | 주택 유형 점수 (`HousingType.classify`; '1형' 같은 값은 분류 불가 → 제외) | 93% |

**쓰지 않는 컬럼:** `supply_type`(2% 채움), `contract_deposit`·`interim_payment`·`balance`(분양 전환형 금액), `pnu`, `heating_method`, `raw_payload`.

## 3. 지원조건 판정 (PASS / CHECK / FAIL)

- **FAIL**(제외): 기준을 넘는 것이 확정된 경우. 연령 밖, 유주택, 기혼인데 미혼 전용, 소득·자산·자동차 초과(다른 순위 가능성도 없을 때).
- **CHECK**(점수 × 0.7, 표시): 사용자가 값을 안 적었거나, 공고 유형을 모르거나, 유형에 규칙이 없거나(영구임대·통합공공임대·일반 매입임대·전세임대), 다른 계층·순위일 가능성이 있을 때.
- **PASS**: 검사한 조건을 모두 충족.

유형별 규칙과 기준값은 `application.yml`의 `zipick.recommendation.eligibility`에 있고 출처는 근거 표에 있다.

| 유형 | 규칙 |
| --- | --- |
| 행복주택 `HAPPY` | 미혼 19~39세, 무주택, 소득 100%(1인 120%, 2인 110%), 총자산 2억 5,100만, 자동차 4,542만. 기혼이면 CHECK(신혼부부 계층) |
| 국민임대 `NATIONAL` | 무주택, 소득 70%(1인 90%, 2인 80%), 총자산 3억 4,500만, 자동차 4,542만 |
| 청년 매입임대 `YOUTH_PURCHASE` | 미혼, 19~39세 또는 대학생·취준생, 무주택, 본인 소득 1인 100%, 총자산 2억 5,100만. 넘으면 2순위 가능성 CHECK(총자산 3억 4,500만 이내) |
| 든든전세 `DEUNDEUN` | 무주택만 |
| 그 외 | CHECK (공고문 확인 필요) |

## 4. 선호 점수 (0~1) 와 가중합

| 항목 | 기본 가중치 | 계산 |
| --- | --- | --- |
| `cost` | 30 | 월 환산 비용 = 월세 + 보증금 × min(10%, 기준금리+2%p) ÷ 12. 예산 이하 1, 30% 초과 0 |
| `region` | 25 | 관심 순위별 1.0 / 0.8 / 0.6, 밖이면 0 (기본 MUST → 제외) |
| `area` | 15 | 범위 안 1, 10㎡ 벗어날 때마다 −0.25. 최저주거기준 미달은 근거에 표시 |
| `rooms` | 10 | 희망 이상 1, 1개 모자랄 때마다 −0.5 |
| `infra` | 10 | 시설별 350m 이내 1, 1,500m 0. `InfraDistanceProvider` 구현 전까지 제외 |
| `age` | 5 | 신축 1, 준공 30년 0 |
| `type` | 5 | 희망 주택 유형 일치 1 |

- 최종 가중치 = 기본 가중치 × 우선순위(1~5), 계산 가능한 항목만으로 정규화.
- 추천도 = 100 × Σ(가중치 × 점수) × 지원조건 배수(PASS 1.0, CHECK 0.7).
- `required-items`(비용·지역)가 없으면 점수 대신 **정보 부족 묶음**으로 간다.
- 순위 묶음: 60점 이상, 점수순(동점 마감 임박순), 공고당 5곳, 최대 30곳. 호실 단위로 점수를 매기고 주택 단위로 묶는다.

## 5. 필수 / 선택 요약

- **온보딩 필수:** 생년월일, 혼인 여부, 세대원 수, 무주택 여부, 관심 지역 1곳 이상.
- **선택:** 소득·자산·자동차(비우면 CHECK), 대학생·취준생, 예산 또는 보증금·월세 상한, 면적 범위, 방 수, 주택 유형, 공공임대 유형(필터용).
