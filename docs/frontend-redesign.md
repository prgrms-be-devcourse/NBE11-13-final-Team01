# 프론트엔드 리디자인 진행 현황

시각 기준은 [DESIGN.md](../DESIGN.md) 한 곳에서 관리한다. 이 문서는 현재 구현 상태와 이후 작업 계획을 구분한다. 실제 라우팅 기준은 `zipick-frontend/src/App.tsx`다.

## 작업 방식

- **1차:** 전체 페이지의 레이아웃·콘텐츠 폭·헤더·컬러·타이포그래피·기본 컨트롤·간격·반응형 통일.
- **2차:** 전체 1차 완료 후 상세 정보, 추천 점수·근거 카드, 캘린더 상호작용, AI 신청 준비 가이드, 클러스터 충돌 회피, 세밀한 애니메이션·사용성 개선.
- 페이지 하나의 세부 UI를 끝까지 고도화하고 다음 페이지로 넘어가지 않는다. 다음 페이지의 실제 구현은 사용자 승인 후 시작한다.

## 구현된 상태

지도는 데스크톱의 기본 안내·상세·추천 패널 폭 400px을 유지한다. 모바일은 기본 안내만 숨기고 선택·추천 패널은 지도 아래에 표시한다. 모드별 데이터 준비 후 한 번 개요를 맞추고, 이후 재조회는 사용자 시점을 유지한다. 전국 보기는 현재 결과 범위를 사용한다. 최대 축소 13과 기존 탐색·필터·URL·선택 동작을 유지한다.

지도 상세 패널은 사진이 없으면 갤러리를 렌더링하지 않고 로드뷰를 그대로 표시한다. 준공·난방·총 세대수와 공급 조건의 선택 값이 없으면 해당 항목만 생략한다. 공급 목록이 비었거나 표시 가능한 공급 값이 없으면 정보 미확인 안내를 표시하며, 기존 공고 원문 버튼과 관심 저장·신청 가이드·추천 점수 기능은 유지한다.

현재 서비스 전체 본문에 공통 테마가 적용된 것은 아니다. 본문 테마는 `/map`, `/calendar`, `/onboarding`, `/tune`에 적용된다. 헤더는 기타 Layout 경로까지 랜딩 기준의 공통 디자인을 사용하며, `/login`, `/signup`은 메뉴가 없는 인증 전용 구조를 유지한다. 모든 헤더는 전체 너비의 `HeaderInner`·공통 정렬/인터랙션 CSS를 공유하고 로고 클릭 시 `/landing`으로 이동한다. 주택 상세는 지도 선택 패널에서 표시한다. 기존 `/houses/:houseId` 주소는 같은 주택을 선택한 `/map?housing={houseId}`로 이동한다. 공통 React Button/Card 라이브러리도 아직 추출되지 않았다.

## 공통 서비스 헤더 프로필 메뉴 (2026-11-01)

- `feat/account-menu`에서 `design-references/zipick-account-menu-concept-v2.html`을 직접 확인하고 `AccountMenu.tsx`·CSS Module을 추가했다. 서비스 메뉴의 내 조건을 우측 계정 메뉴로 옮겼으며, 이메일·로그아웃은 패널에 한 번만 표시한다. 랜딩·인증 전용 헤더·온보딩 1·2·3단계·본문·공유 CSS·브랜드 파일은 변경하지 않았다.
- 사용자 표시는 기존 `useAuth`의 `userId`·이메일만 사용한다. 이름/닉네임 필드가 없어 `집픽 사용자`를 표시하며 이메일이 없으면 생략한다. 기존 `GET /api/users/me`로 채워진 상태를 재사용하므로 메뉴 열기 자체에는 API 요청이 없다. 인증 제공자 조건·새로운 개인정보·DB/회원가입 변경은 없다.
- 내 조건 링크는 기존 `/onboarding`이다. `GET/PUT /api/v1/profiles/me`, `/preferences`와 3단계 AHP 동작은 기존 화면에 그대로 둔다. 로그아웃도 기존 `logout()` → `POST /api/auth/logout` → 세션 정리 → `qc.resetQueries()`·`closeGate()` → `/map` 이동 순서를 유지한다.
- 조사 결과: 내 계정은 `GET /api/users/me` 조회만 있으며 정보 수정 API/화면은 없다. 알림 설정은 `GET/PUT /api/v1/notifications/settings`, 테스트 `POST /api/v1/notifications/test`, 내역 `GET /api/v1/notifications`와 기존 `/calendar`의 `NotificationPanel`이 존재한다. 광고성 정보 수신 동의와 동의 시각도 알림 설정에 있으나 일반 약관·개인정보 동의 내역/변경 기능은 없다. 이번 범위에서는 세 항목 모두 계정 메뉴에 연결하지 않고 클릭/포커스 없는 `준비 중` 목록으로 표시한다. 알림 설정 안내는 기존 기능 부재로 오해하지 않도록 계정 메뉴 연동이 추후 제공된다고 명시한다.
- lint/build 통과. Headless Chrome의 대체 인증/API로 30개 검증 묶음을 통과했다. 1440/390/320px 로그인·비로그인 헤더, 실제 상태 이메일·이메일 없음·긴 이메일, 클릭 토글·외부 pointer·ESC·포커스 복귀, Enter/Space·Tab/Shift+Tab·focus-visible, 준비 중 항목의 비활성, 메뉴 선택·페이지/쿼리/해시/뒤로 이동 시 닫힘, 계정 전환, `/onboarding` 저장값 복원·편집 중 입력 유지·2/3단계 표시, 로그아웃 요청 Authorization·토큰 정리·비회원 헤더·기존 목적지·API 실패 후 세션 정리를 확인했다. 320/390/720/721/768/980/1440px에서 긴 이메일과 페이지/패널 가로 넘침이 없으며 320px 높이에서는 내부 스크롤로 로그아웃에 접근한다. 1440/320px 캡처를 직접 확인했고 모션 감소를 확인했다. 런타임 예외는 없었다.
- 실제 로컬 백엔드에는 인증 없이 `GET /api/users/me`, `GET /api/v1/profiles/me`, `GET /api/v1/notifications/settings`를 요청해 모두 401 차단을 확인했다. 이는 실제 계정 로그인·JWT 재발급·서버 로그아웃/쿠키 만료·온보딩 저장 영속화 검증을 의미하지 않는다. 해당 실인증 흐름·알림 발송·지도 SDK·다른 브라우저는 미검증이다. 백엔드 기능 확인은 소스 조사, 로그인한 UI/로그아웃 상호작용은 대체 API 검증으로 구분한다.
- 시작 시 브랜치는 `feat/account-menu`이고 작업 트리·index·stash는 비어 있었다. 디자인 레퍼런스는 기존 로컬 ignore 상태를 유지하며 staging/commit/push·브랜치 전환·stash 조작을 하지 않았다. 후속 페이지 작업 범위와 순서는 변경하지 않는다.

## 로그인·온보딩 공통 안내 UI (2026-10-31)

- `AuthGateModal`과 `AccessGate`에 각각 CSS Module과 자체 테마 범위를 적용했다. 팝업은 최대 400px, 접근 안내는 최대 500px·가로 중앙 정렬이며 ZIPICK 카드·타이포그래피·인증 버튼 규칙을 사용한다. 공통 장식 SVG를 `AuthGateIcon`으로 분리하고 로그인/관심 저장/조건 입력/조회 오류를 구별한다. 로그인 접근 안내의 설명·CTA는 사용자 지정 문구를 적용했다.
- 게이트 판정·effect 의존성·상태 스토어·API·이동/복귀·보류 저장·재시도 코드는 유지했다. 팝업 설명을 접근성 이름과 연결하고 로딩에 status 역할을 추가했다. 기존 전역 스타일과 다른 페이지·헤더·브랜드·favicon 파일은 수정하지 않았다.
- lint/build 통과. Headless Chrome의 대체 인증/API 및 보류 상태 주입으로 33개 검증 묶음을 통과했다. 1440/390/320px에서 캘린더 자동 표시, X/ESC/배경/나중에 닫기와 재열기, 세 팝업·접근 안내·오류/로딩, 내 조건 이동, 로그인/가입 이동·계정 전환·로그인 후 경로/쿼리 복귀, 관심 공고 보류 상태 유지·로그인 후 정확히 1회 저장, 두 조건 조회 오류·재시도를 확인했다. 실제 마우스 hover·Tab/Shift+Tab·포커스 표시·모션 감소·가로 넘침 없음과 낮은 320px 높이에서 팝업 내부 스크롤도 확인했다. 런타임 예외는 없었다.
- 변경 전 두 컴포넌트를 임시 Vite 서버에서 로드해 변경 후와 비교했다. 로그인·가입·랜딩·지도·로그인한 캘린더/조건 입력/취향 찾기 및 운영자 화면의 안내 카드를 제외한 영역에서 3개 너비의 24쌍 캡처가 픽셀 단위로 동일했다. 확인한 일부 안내 화면 캡처도 직접 검토했다. 지도는 대체 데이터이므로 실제 SDK 검증을 의미하지 않는다.
- 실제 계정 인증·회원가입·메일 발송·서버 저장 영속화·실제 지도 SDK·다른 브라우저/글꼴은 미검증이다. 기존 작업 파일 해시와 index 내용을 비교해 기존 변경 및 13개 staged 파일·favicon의 추가 수정을 보존했음을 확인했다. 브랜치 전환·staging/commit/push·stash 조작은 하지 않았다. 다른 페이지의 완료 상태나 작업 순서는 변경하지 않는다.

## 랜딩 기준 전체 헤더 통일 (2026-10-31)

- `Layout`의 서비스·기존 레거시 헤더와 `AuthLayout`을 랜딩 기준으로 통일했다. 데스크톱 높이 88px, 로고 40px(720px 이하 36px), 로고–메뉴 간격 54px, 메뉴 15px/550/1.65·간격 37px, 버튼 44px/반경 10px/15px·650을 적용한다. 980px 이하에서는 로고–메뉴 및 메뉴 항목 간격을 24px로 줄인다. 모바일 버튼은 높이 38px·12px이며 서비스 메뉴의 2행/가로 스크롤과 랜딩의 기존 숨김 정책을 유지한다.
- 공통 `HeaderInner`는 최대 폭 제한 없이 기존 32/22/16/14px 여백을 사용하며, 헤더 우측 패딩만 실제 스크롤바 예약 너비만큼 보정한다. 1440px에서 랜딩·서비스·인증의 로고 왼쪽 32px·우측 행동 끝 1408px이 일치한다. 서비스·인증 로고는 접근성 이름이 있는 Link로 `/landing`에 연결하고 이미 같은 경로인 랜딩 로고는 유지했다. 메뉴 링크·활성 밑줄·인증 노출·복귀 state·로그아웃 정책은 그대로다.
- MapLayout에서는 헤더 선언만 공통 CSS로 옮겼다. 인증 CSS는 헤더 높이 차감을 기존 73/66px에서 88/68px로 맞추는 두 선언만 변경했고, 카드·본문 폭/패딩은 유지했다. 브랜드·favicon·안내 UI·지도 SDK·본문 소스/CSS·레퍼런스 파일은 변경하지 않았다. 헤더 높이 증가에 따라 본문 시작 위치는 이동한다.
- lint/build 통과. Headless Chrome + 대체 인증/API로 24개 검증 묶음을 통과했다. 1440/390/320px의 전체 헤더와 로그인 상태별 노출·긴 이메일·로고 이동·메뉴 경로/활성 상태·우측 정렬·hover/focus·모션 감소·로그아웃·인증 복귀 state·기존 안내 팝업을 확인했다. 실제 모바일 에뮬레이션과 681/720/721/768/980/981/1100/1920px에서도 메뉴 겹침·가로 넘침 없이 동작했다. 스크롤바가 있는 좁은 데스크톱 에뮬레이션에서는 우측 여백의 0px 하한 때문에 화면 끝 기준 최대 1px 차이가 있고, 모바일 오버레이 환경에서는 좌우 기준이 일치한다.
- 랜딩/지도 포함 9개 화면의 변경 전후 캡처를 3개 너비에서 비교했다. 본문 자손의 텍스트·구조 및 주요 computed style 27쌍이 동일했다(CSS Module 생성 클래스 이름 제외). 본문 폭/패딩·인증 카드 너비/높이·헤더 아래 상대 여백도 동일했다. 인증 main의 남은 높이가 바뀌므로 배경 그라디언트의 위치와 카드 둥근 모서리 바깥 배경 픽셀까지 동일하다는 의미는 아니다. 실제 지도 SDK는 검증 환경에서 로드되지 않았으며 실제 계정 인증·서버 권한·데이터·다른 브라우저/글꼴은 미검증이다.
- 작업 시작 시 `feat/auth-pages-redesign`의 작업 트리·index·stash는 비어 있었다. 기존 commit과 완료된 작업 파일을 보존했으며 staging/commit/push·브랜치 전환·stash 조작은 하지 않았다. 본문 페이지의 완료 상태와 후속 작업 순서는 변경하지 않는다.
