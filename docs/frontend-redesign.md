# 프론트엔드 리디자인 진행 현황

## Pretendard 웹폰트 프로젝트 포함 (2026-11-02)

- 사용자 컴퓨터에서는 설치된 Pretendard Regular/ExtraBold가 사용되고 있었지만 프로젝트에는 폰트 리소스가 없어 컴퓨터마다 글꼴이 달라지는 구조였다. 공식 v1.3.9 원본 `PretendardVariable.woff2`(2,057,688바이트)와 SIL OFL 라이선스·출처/버전/SHA-256 안내를 `public/fonts/pretendard/`에 포함했다.
- `design-system/fonts.css`의 `@font-face`는 같은 출처의 URL만 사용하고 굵기 45–920·normal·swap을 선언한다. 전역 폰트 토큰으로 본문·서비스·인증·헤더·랜딩을 연결하고 `index.html`에 동일 URL의 CORS preload를 추가했다. 색상·패널 토큰의 테마 범위와 기존 글자 크기·굵기·행간·라우팅·인증·API는 유지했다. 이미지로 제공되는 지도 자체 글자는 변경하지 않았다. CDN·새 패키지 의존성은 추가하지 않았다.
- lint/build와 `git diff --check` 통과. 배포 빌드의 폰트·LICENSE·출처 파일이 원본과 바이트 단위로 일치함을 확인했다. 개발 서버와 배포용 빌드 preview의 1440/1024/390px에서 랜딩·로그인·회원가입·지도·관심 공고 일정·조건 입력을 검증했다. Chrome의 로컬 CSS 폰트 사용을 끈 환경에서도 실제 렌더링 폰트가 다운로드된 Pretendard인지 확인했고, 한 번의 같은 출처 폰트 요청·preload 재사용·가로 넘침 없음·설치 폰트 사용 여부에 따른 글꼴/히어로 크기 동일·가변 굵기·다운로드 실패 시 읽기 가능한 대체 글꼴을 포함해 190개 항목을 통과했다. 폰트 파일은 실제 프로젝트 리소스를 사용하고 인증·API·지도 SDK는 대체했다.
- 팀원 실제 컴퓨터·배포 서버·다른 OS/브라우저·실제 계정 인증은 미검증이다. 검증 결과·캡처·임시 스크립트는 OS 임시 폴더 `zipick-webfont-review` 및 인접 위치에 보관했다. 기존 `fix/landing-auth-header` 브랜치를 유지했고 이번 폰트 변경은 staging/commit/push하지 않았다.

## 랜딩 헤더 로그인 상태 반영 (2026-11-02)

- 로그인 상태와 무관하게 로그인 링크를 표시해 클릭 시 로그인 페이지에서 랜딩으로 즉시 되돌아오던 문제를 수정했다. `LandingHeader`가 기존 `useAuth`를 구독하고 로그인 상태에는 공통 `AccountMenu`, 비회원에는 기존 로그인 링크를 표시한다. 내 조건 링크와 계정/URL 변경 시 메뉴 초기화를 재사용하고, 로그아웃은 기존 인증 모듈·쿼리 초기화·게이트 닫기 후 공개 랜딩에 머문다. 공유 계정 메뉴·인증 API·서비스 Layout은 수정하지 않았다.
- 랜딩 CSS에서만 메뉴 패널의 기준을 우측 행동 영역으로 지정하고 모바일 간격을 조정했다. 1440/1024/390/320px의 메뉴·CTA 배치와 패널/페이지 가로 넘침 없음, 로그인 복원/서비스에서 홈 복귀/로그인 폼 후 복귀의 상태 반영, 계정 정보, 내 조건 이동, 키보드/ESC/외부 클릭, 로그아웃 성공/실패 시 세션 정리를 대체 인증·API·SDK의 Chrome 브라우저 53개 항목으로 확인했다. 카카오 이메일 미제공 표시도 대체 사용자로 확인했으며 실제 계정 인증·실제 서버 로그아웃·실제 카카오 로그인은 미검증이다.
- `npm run lint`, `npm run build`, `git diff --check` 통과. `dev` 브랜치와 staging/stash를 유지하고 commit/push·PR 생성은 하지 않았다. 검증 스크립트·캡처는 OS 임시 폴더에만 보관한다.

지도는 데스크톱의 기본 안내·상세·추천 패널 폭 400px을 유지한다. 모바일은 기본 안내만 숨기고 선택·추천 패널은 지도 아래에 표시한다. 모드별 데이터 준비 후 한 번 개요를 맞추고, 이후 재조회는 사용자 시점을 유지한다. 전국 보기는 현재 결과 범위를 사용한다. 최대 축소 13과 기존 탐색·필터·URL·선택 동작을 유지한다.

지도 상세 패널은 사진이 없으면 갤러리를 렌더링하지 않고 로드뷰를 그대로 표시한다. 준공·난방·총 세대수와 공급 조건의 선택 값이 없으면 해당 항목만 생략한다. 공급 목록이 비었거나 표시 가능한 공급 값이 없으면 정보 미확인 안내를 표시하며, 기존 공고 원문 버튼과 관심 저장·신청 가이드·추천 점수 기능은 유지한다.

현재 서비스 전체 본문에 공통 테마가 적용된 것은 아니다. 본문 테마는 `/map`, `/calendar`, `/onboarding`, `/tune`에 적용된다. 헤더는 기타 Layout 경로까지 랜딩 기준의 공통 디자인을 사용하며, `/login`, `/signup`은 메뉴가 없는 인증 전용 구조를 유지한다. 모든 헤더는 전체 너비의 `HeaderInner`·공통 정렬/인터랙션 CSS를 공유하고 로고 클릭 시 `/landing`으로 이동한다. 주택 상세는 지도 선택 패널에서 표시한다. 기존 `/houses/:houseId` 주소는 같은 주택을 선택한 `/map?housing={houseId}`로 이동한다. 공통 React Button/Card 라이브러리도 아직 추출되지 않았다.

## 랜딩 목업 HTML 시안 반영 (2026-11-01)

- 사용자 승인 범위인 랜딩에만 `design-references/zipick_landing_refined_mockups.html`을 최우선 기준으로 적용했다. 히어로는 지역명·주택 수 클러스터, 개별 핀, 검색·주택 수와 상태/LH/관심 공고/주소/공급 정보 플로팅 카드로 교체했다. 히어로 높이·좌우 비율·왼쪽 문구·버튼은 유지했다.
