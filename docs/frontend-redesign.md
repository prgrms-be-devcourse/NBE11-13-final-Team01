# 프론트엔드 리디자인 진행 현황

시각 기준은 [DESIGN.md](../DESIGN.md) 한 곳에서 관리한다. 이 문서는 현재 구현 상태와 이후 작업 계획을 구분한다. 실제 라우팅 기준은 `zipick-frontend/src/App.tsx`다.

## 작업 방식

- **1차:** 전체 페이지의 레이아웃·콘텐츠 폭·헤더·컬러·타이포그래피·기본 컨트롤·간격·반응형 통일.
- **2차:** 전체 1차 완료 후 상세 정보, 추천 점수·근거 카드, 캘린더 상호작용, AI 신청 준비 가이드, 클러스터 충돌 회피, 세밀한 애니메이션·사용성 개선.
- 페이지 하나의 세부 UI를 끝까지 고도화하고 다음 페이지로 넘어가지 않는다. 다음 페이지의 실제 구현은 사용자 승인 후 시작한다.

## 구현된 상태

| 화면 | 경로 | 상태·접근 조건 |
| --- | --- | --- |
| 랜딩 | `/landing` | 1차 완료. 독립 레이아웃·CSS Modules·예시 목업 유지 |
| 관심 공고·일정 | `/calendar` | 1차 구현 완료. 로그인 필요. 검증 범위는 아래 기록 참조 |
| 지도·맞춤 추천 | `/map`, `/map?mode=recommended` | 1차 완료. 전체 공고는 공개, 추천은 로그인·조건 입력 필요 |
| 조건 입력 | `/onboarding` | 1·2단계 디자인 적용. 공통 안내·Stepper 유지. 3단계 AHP는 기존 UI. 로그인 필요 |

지도는 데스크톱의 기본 안내·상세·추천 패널 폭 400px을 유지한다. 모바일은 기본 안내만 숨기고 선택·추천 패널은 지도 아래에 표시한다. 모드별 데이터 준비 후 한 번 개요를 맞추고, 이후 재조회는 사용자 시점을 유지한다. 전국 보기는 현재 결과 범위를 사용한다. 최대 축소 13과 기존 탐색·필터·URL·선택 동작을 유지한다.

지도 상세 패널은 사진이 없으면 갤러리를 렌더링하지 않고 로드뷰를 그대로 표시한다. 준공·난방·총 세대수와 공급 조건의 선택 값이 없으면 해당 항목만 생략한다. 공급 목록이 비었거나 표시 가능한 공급 값이 없으면 정보 미확인 안내를 표시하며, 기존 공고 원문 버튼과 관심 저장·신청 가이드·추천 점수 기능은 유지한다.

현재 서비스 전체 공통 테마가 적용된 것은 아니다. `Layout`의 새 헤더 테마는 `/map`, `/calendar`, `/onboarding`에 적용되고 다른 서비스 페이지는 기존 스타일이다. 주택 상세는 지도 선택 패널에서 표시한다. 기존 `/houses/:houseId` 주소는 같은 주택을 선택한 `/map?housing={houseId}`로 이동한다. 공통 React Button/Card 라이브러리도 아직 추출되지 않았다.

## 이후 1차 권장 순서

남은 페이지에도 공통 Layout·헤더·기본 스타일을 단계적으로 적용한다. 현재 새 헤더 적용 범위는 지도·관심 공고·일정·조건 입력이며, 공유 헤더를 전면 변경한 상태는 아니다.

| 순서 | 화면·실제 경로 | 접근 및 보존 조건 |
| --- | --- | --- |
| 1 | 신청 준비 가이드 `/interest-notices/:noticeId/guide` | 로그인·실제 공고 ID·관심 저장 등 서버 선행 조건 유지 |
| 2 | 취향 찾기 `/tune` | 로그인·온보딩 완료 필요. 비교·우선순위 동작 보존 |
| 3 | 로그인 `/login`, 회원가입 `/signup` | 공개 인증 화면. 로그인 기본 `/map`, `state.from` 복귀 유지 |
| 4 | 조건 입력 `/onboarding` | 1·2단계 적용. 3단계 디자인은 별도 승인 후 진행. 로그인·저장 흐름 보존 |
| 5 | 운영자 캠페인 `/admin/campaigns` | 프론트 로그인 관문 및 서버 관리자 권한 확인 유지 |
| 마지막 | 전체 페이지 일관성·반응형 검증 | 단계별 적용 누락, CSS 누출, 접근성·기능 회귀 확인 |

`LandingPage`, `MapPage`, `CalendarPage`, `ApplicationGuidePage`, `TunePage`, `LoginPage`, `SignupPage`, `OnboardingPage`, `AdminCampaignPage`가 현재 독립 화면 컴포넌트다. 추천과 주택 상세는 별도 페이지가 아니라 지도 모드·선택 패널이다.

## 진입·호환 라우트

| 경로 | 현재 동작 |
| --- | --- |
| `/` | `/landing`으로 replace 리다이렉트 |
| `/landing` | 랜딩 직접 표시 |
| `/map` | 지도 직접 표시 |
| `/houses/:houseId` | `/map?housing={houseId}`로 replace 리다이렉트 |
| `/houses` | `/map` 리다이렉트, 다른 쿼리 유지·mode 제거 |
| `/recommendations` | `/map?mode=recommended` 리다이렉트, 다른 쿼리 유지 |

위 리다이렉트는 별도 디자인 페이지가 아니다. 사이트 기본 진입만 랜딩으로 변경했다. `LoginPage.DEFAULT_LANDING`은 이름과 달리 계속 `/map`이고, 로그인·가입의 `state.from`, AuthGateModal의 복귀 경로, 로그아웃 후 이동은 변경하지 않는다.

## 2차로 보류한 항목과 알려진 제한

- 지도 상세 정보 구성과 추천 점수·근거·카드의 세부 UI.
- 캘린더 상호작용, AI 신청 가이드의 세부 정보 표현.
- 서울·경기·인천 등 밀집 지역의 화면 좌표 기반 충돌 회피·라벨 배치. 집계나 실제 좌표를 임의로 옮기지 않는다.
- 세밀한 모션과 페이지별 사용성 개선.
- 작은 화면·최대 축소 13에서는 모든 분산 좌표가 한 화면에 들어오지 않을 수 있다. 안내와 목록을 유지한다.
- SDK 지도 제공 범위 경계에서 빈 영역이 남는 경우가 있으며, 반응형 전환 시 SDK의 픽셀 좌표 반올림도 검증 대상으로 남는다. 1차 디자인 완료가 모든 SDK 제한의 해소를 의미하지 않는다.

## 공통 기능 보존·검증

- API·백엔드·배포·추천 점수·권한·필터·상태 관리 계약은 디자인 변경 범위에 포함하지 않는다.
- URL 모드·필터·선택 ID, 뒤로/앞으로, 로그인·가입 후 복귀, 관심 저장 선행 조건을 보존한다.
- 공통 상세·필터 등 공유 컴포넌트 변경 시 지도 및 독립 페이지 양쪽을 확인한다. 페이지 루트 테마와 CSS Modules를 사용하고 전역 CSS 일괄 교체를 피한다.
- 지도는 SDK 인스턴스, 선택 상태, 최대 축소 13, 모드 진입당 개요 맞춤, 일반 이동·재조회 시 시점 유지, 패널 개폐·반응형 relayout, 클러스터 단계 동기화를 확인한다.
- `npm run lint`, `npm run build`를 실행하고 1440px·390px, 필요 시 1920px에서 확인한다. 로딩·오류·빈 결과·비회원·조건 미완료도 검증한다.
- 실제 데이터·실제 회원 인증·브라우저 대체 응답을 구분한다. 기존 지도 추천 전환의 예외 시나리오는 대체 응답으로 검증한 부분이 있으며 실제 회원 추천 API 연동 전체가 검증됐다고 간주하지 않는다.
- 완료 보고에는 이번 변경 파일, 실제 실행한 검증, 남은 문제·미검증 항목을 기록한다. 기존 변경·stash 보존, 임의 commit·push·브랜치 전환 금지를 유지한다.


## 관심 공고·일정 1차 작업 결과 (2026-10-30)

- 데스크톱 달력 + 다가오는 일정, 저장 공고 2열, 알림 설정 순서로 정리했다. 태블릿·모바일은 한 열이며 범례와 행동 버튼은 줄바꿈한다. DESIGN.md와 실제 지도 토큰·선언을 우선했다.
- 지도 서비스 셸을 `/calendar`에도 적용했다. 본문은 신규 CalendarPage.module.css로 격리했고 전역 styles.css, 지도 본문 CSS, 라우팅·API·쿼리 키·인증 로직은 변경하지 않았다.
- 관심 목록·일정·알림 설정·내역에 로딩·오류·빈 상태와 조회 재시도를 추가했다. 최초 설정 조회 전에는 알림 폼을 비활성화한다. 기존 월 이동·관심 해제·웹훅 유지 의미·알림 저장/테스트·공고 원문·실제 noticeId 가이드 링크를 유지했다.
- `npm run lint`, `npm run build` 통과. lint는 `tsc --noEmit`, build는 TypeScript 프로젝트 빌드와 Vite 프로덕션 빌드다.
- Headless Chrome + 브라우저 API 대체 응답으로 1440/1100/1099/720/390/320px의 페이지 가로 넘침 없음과 범례 표시를 확인했다. 1440px·390px 스크린샷으로 배치를 확인했다.
- 대체 응답에서 월 이동·빈 월·오늘 복귀, 관심 해제 후 목록/일정 갱신, 빈 목록, 목록/일정/알림 설정/내역의 독립 오류, 일정 재시도, 로딩 시 0건 오표시 방지, 기존 웹훅 유지 저장 payload, 테스트 발송 결과 표시, 비회원 접근 차단을 검증했다. 실제 알림은 발송하지 않았다. 런타임 예외는 없었다.
- 실제 회원 인증·관심 저장/해제의 서버 영속화·알림센터 발송·AI 생성·Kakao 지도 동작은 이번 브라우저 검증에 포함하지 않았다. 로그인 화면의 기존 셸 유지와 랜딩 분리는 확인했다. 모든 미전환 페이지의 시각 회귀·전체 키보드 탐색은 미검증이다.
- 복잡한 캘린더 상호작용·저장 카드와 알림 설정 흐름 재설계·주택 상세 패널 세부 디자인·가이드 자체 디자인은 2차에 남긴다. 다른 페이지 구현은 시작하지 않았다.

### 콘텐츠 높이·표시 범위 보완

- 사용자 요청으로 데스크톱 다가오는 일정 패널을 달력 높이에 맞추고, 제목·표시 건수를 제외한 목록만 내부 스크롤하도록 변경했다. 오른쪽 일정이 그리드 행 높이를 늘리지 않는다. 기존 정렬과 최대 8개 제한은 유지했다.
- 한 열 배치(1099px 이하)에서는 일정 3개를 먼저 표시하고 더 보기/접기로 나머지를 확인한다. 내부 스크롤은 사용하지 않는다.
- 저장 공고는 기존 조회 결과를 클라이언트에서 4개씩 페이지네이션한다. 기존 카드와 전체 건수를 유지하고, 이전/다음·현재/전체 페이지를 표시한다. 마지막 페이지가 비면 유효한 이전 페이지로 이동한다. API·캐시 키·월 이동·관심 해제·인증·알림 로직은 변경하지 않았다.
- lint/build 통과. Headless Chrome의 대체 API 응답으로 1440px·390px 각각 저장 공고 0/1/5/10개, 페이지별 카드 수·전체 건수·이전/다음 경계·실제 noticeId 링크·삭제 후 페이지 보정을 검증했다. 마지막 1개 삭제의 빈 상태도 확인했다.
- 일정 12개 응답 중 최대 8개 표시, 데스크톱 패널/달력 높이 일치·목록 스크롤·제목 고정·월 이동 후 높이 동기화, 모바일 3개/8개 더 보기·접기를 확인했다. 1440/1100/1099/390/320px 가로 넘침 없음과 반응형 전환을 확인하고 1440px·390px 스크린샷을 검토했다. 페이지 이동 시 추가 API 요청과 런타임 예외는 없었다.
- 실제 회원 인증·서버 영속화·외부 알림 발송 검증은 이번에도 수행하지 않았다. 복잡한 캘린더 기능과 다른 페이지 구현은 진행하지 않았다.

## 조건 입력 2단계 작업 결과 (2026-10-31)

- 승인된 `design-references/zipick-onboarding-step2-region-final-adjusted.html`을 기준으로 2단계만 구현했다. 기존 칩 나열을 시·도/시·군·구 탐색기와 현재 시·도 검색으로 바꾸고, 상단 선택 요약에 저장된 우선순위·개수·삭제를 표시한다. 목록은 기존 API 응답만 사용하며 주택 수, 최대 3곳, 중복 방지, 삭제 후 순위 재정렬을 유지한다.
- 1단계와 같은 카드 폭·패널 토큰·회색 필수/선택 표시를 사용한다. 예산, 면적·방 수, 선호 유형을 구분선으로 나누고 숫자 입력은 높이 48px·단위 표시·2열 배치, 작은 화면은 1열로 전환한다. 전역 `styles.css`와 1·3단계·공통 안내·Stepper는 변경하지 않았다.
- API·쿼리 키·payload·지역 식별값·유형 정의·추천 계산은 유지한다. 최초 희망 조건 조회만 초안에 복원하여 재조회가 편집을 덮지 않게 하고, 조회 중·오류·재시도를 구분한다. 저장 성공 시 기존 3단계로 이동한다. 빠른 연속 제출을 잠그고 저장 실패 후 다시 저장할 수 있다.
- 기존 양수 예산 판정에는 월 예산도 포함되므로 시안과 달리 안내에도 월 예산을 포함했다. 필수 누락 시 버튼 클릭으로 인라인 오류와 포커스를 제공하되 요청·단계 이동은 차단한다. 금액·면적·방 수의 네이티브 제약을 유지하고 서버와 같은 면적 범위 규칙을 화면에서 먼저 안내한다.
- lint/build 통과. Headless Chrome과 대체 인증·API 응답으로 15개 검증 묶음을 통과했다. 지역 검색·선택·3곳 제한·해제·순위·복원, 숫자 제약·면적 오류·선택 항목 공란·유형 다중 선택, 단계 왕복과 재조회 시 초안 유지, 조회 오류·재시도·신규 404, 저장 실패·동시 중복 제출 차단·payload·3단계 이동, 비회원 관문을 확인했다. 런타임 예외는 없었다.
- HTML과 React를 1440px·390px에서 각각 렌더링하고 캡처를 비교했다. 데스크톱 카드 692px, 모바일 358px로 1단계와 동일하다. 지역 탐색기는 같은 대체 목록에서 HTML과 폭·높이가 일치한다. 320/380/390/680/720/768/1440px에서 페이지 가로 넘침이 없고 긴 지역명도 줄바꿈한다. 1·3단계 콘텐츠는 변경 전후 픽셀이 동일하다. 모바일 1단계는 스크롤바 숨김 설정에 따라 캡처 하단 배경 여백만 18px 차이가 있고, 나머지 세 캡처는 PNG 해시도 동일하다.
- 실제 회원 인증·서버 영속화·운영 지역 응답·추천 재계산 결과는 미검증이다. 시안과의 의도된 차이는 확정된 공통 헤더·Stepper 유지, 1단계의 글꼴 규칙·브랜드 토큰 적용, 실제 주택 수와 기존 기능 설명·예산 정책 유지다. 3단계 리디자인과 다른 페이지 구현은 시작하지 않았다.

### 예산 그룹 배치·검증 UI 보완

- 월 예산을 예산 섹션의 전체 너비 두 번째 행으로 이동했다. 면적·방 수는 세 항목의 기존 2열 정렬을 유지한다. 사용자 지정 설명·오류 문구와 월 예산 도움말을 적용했다.
- 기존 `hasBudget` 판정을 그대로 사용하여 저장 시 세 예산 입력창에 필수 오류를 함께 표시하고 양수 입력 즉시 해제한다. 숫자 제약·API·저장 필드·중복 제출 방지·단계 이동은 변경하지 않았다.
- lint/build 통과. Headless Chrome의 대체 인증·API로 최초 오류 미표시, 그룹별 필드 배치, 공란·0·음수의 저장 차단과 오류 테두리, 양수 입력 시 필수 오류 해제, 별도 숫자 범위·정수 제약, 각 예산 항목 단독 저장·3단계 이동·재조회 복원, 단계 왕복 초안 유지를 검증했다. 1440px·390px 캡처에서 전체 너비 월 예산 행, 48px/16px 입력창, 중앙 정렬과 가로 넘침 없음을 확인했다. 실제 인증·서버 영속화·추천 계산은 미검증이다.
