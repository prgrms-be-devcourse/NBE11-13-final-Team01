# 지도 핀 군집화 — 행정구역 기준 (현재 구현)

ZIPICK 지도는 전체 공고와 맞춤 추천을 같은 `MapPanel` 위에서 전환해 보여 준다.
공급주택이 수백 곳이라 핀을 그대로 뿌리면 겹쳐서 읽을 수 없다.

ZIPICK 은 **화면 좌표가 가까운 핀을 묶는 일반 클러스터링을 쓰지 않는다.**
**행정구역 자체가 탐색 단위**다 — 축소하면 시·도, 중간에서는 시·군·구, 더 확대하면 개별 주택이다.
군집에는 숫자만이 아니라 **지역명 + 고유 주택 수**가 함께 뜬다.

> 카카오 SDK 의 `MarkerClusterer`(`libraries=clusterer`)는 더 이상 쓰지 않는다. 2026-10-29 에 로더에서 제거했다.

---

## 1. 구조

```
features/map/
  MapPanel.tsx      지도 인스턴스 생성·유지, 선택 상태, 확대 버튼, 전국 보기
  clustering.ts     카카오 Marker·CustomOverlay 로 그리고 치운다 (SDK 의존)
  regionCluster.ts  무엇을 어떻게 묶을지 (SDK 무의존 순수 함수)
  locationGroup.ts  같은 좌표 주택 묶기 + 보수적 중복 제거 (SDK 무의존 순수 함수)
  kakaoMaps.ts      SDK 로더 + 타입
  types.ts          MapPin 계약
```

`MapPanel` 은 지도를 한 번만 만들고, 핀 목록이 바뀌면 `clustering.ts` 가 돌려주는 `PinLayer` 에 넘긴다.

```ts
export interface PinLayer {
  render(pins: MapPin[]): void;                       // 핀 목록 통째 교체
  highlight(housingId, locationHousingIds?): void;     // 선택 강조 (지도는 안 움직인다)
  resetStage(): void;                                  // 탐색 단계 초기화 (지도는 안 움직인다)
  destroy(): void;                                     // 마커·오버레이·리스너 정리
}
```

**SDK 에 기대는 판단을 순수 함수 쪽에 두지 않는다.** 그래서 묶는 규칙은 테스트와 수정이 쉽고,
대표 좌표 방식이나 레벨 경계를 바꿀 때 `regionCluster.ts` 한 곳만 보면 된다.

## 2. 기본 확대 단계

카카오 지도는 **숫자가 클수록 축소**다(1 = 최대 확대).

| 레벨 | 단위 | 표시 |
| --- | --- | --- |
| `>= 11` | 시·도 | `경기도 54` `강원특별자치도 80` |
| `7 ~ 10` | 시·군·구 | `강원 · 원주시 16` `서울 · 종로구 5` |
| `<= 6` | 개별 주택 / 위치 | 일반 핀, 같은 좌표면 숫자 배지 핀 |

```ts
export const CLUSTER_LEVELS = { province: 11, district: 7 } as const;
```

경계값은 `regionCluster.ts` 상수 하나로 모아 두었다. **실화면에서 조정할 때 이 상수만 고친다.**

### 시·군·구 라벨에 시도를 함께 쓰는 이유

`중구`·`동구`·`북구`·`남구` 는 여러 시도에 같은 이름으로 있다. 그래서 라벨은 `강원 · 원주시` 형식이다.
(그룹 key 는 처음부터 시도를 포함하고 있어 **데이터는 섞인 적이 없다 — 라벨만의 문제였다.**)
표시용 짧은 시도명은 `shortProvince()` 가 만든다. 저장된 값은 건드리지 않는다.

### 주택이 1곳인 지역도 군집으로 보여 준다

`MIN_CLUSTER_SIZE = 1` 이다. 행정구역이 탐색 단위이므로 축소 상태에서는 "그 지역에 몇 곳인가"가 읽혀야 한다.
2 이상으로 올리면 주택 1곳인 지역만 개별 핀으로 떨어져 나와 같은 확대 수준에서 단위가 섞여 보인다.

## 3. 군집 클릭 — 탐색 단계(semantic stage)

군집을 누르면 **그 군집에 묶인 주택 좌표 전체로 `fitBounds`** 하고, 지도를 다음 탐색 단계로 들여보낸다.

```
province 군집 클릭 → 그 시도 주택 전체 fitBounds → 단계 = district
district 군집 클릭 → 그 시군구 주택 전체 fitBounds → 단계 = individual
```

### ⚠️ 강제 `setLevel` 을 쓰지 않는다

`fitBounds` 로 맞춘 확대 수준을 **이후 절대 건드리지 않는다.**
예전에는 다음 단계를 띄우려고 레벨을 한두 칸 강제로 당겼는데, 그러면 `fitBounds` 가 보장한 범위가 깨져
주택이 화면 밖으로 밀려났다(실측: 원주 16곳 → 0곳, 춘천 42 → 25, 달성군 19 → 4).
지도 뷰포트는 `fitBounds` 결과 그대로 두고, **표시 단계만 따로 기억한다.**

유일한 예외는 좌표 범위가 사실상 한 점일 때다(주택 1곳, 같은 단지 중복 공고).
범위가 0이면 최대 확대로 튀므로 `SINGLE_PIN_LEVEL = 5` 로 맞춘다.

### 단계는 화면 전체에 같이 적용된다

```ts
export interface StageOverride {
  unit: 'district' | 'none';   // 들어간 단계 ('none' = 개별/위치)
  level: number;               // 들어간 시점의 확대 수준 = 해제 기준점
}
```

**누른 지역만 펼치지 않는다.** 처음에는 지역별로 단계를 줬는데, 그러면 경기도를 눌렀을 때
경기만 시군구이고 같은 화면의 서울·강원은 시도로 남아 한 화면에 단위가 섞였다.

역할을 나눈다.

```
누른 군집       → 어디를 볼지 (fitBounds 대상)
StageOverride   → 어떤 단계로 볼지 (화면 전체)
```

### 기본 단계와 탐색 단계 중 더 자세한 쪽을 쓴다

```ts
effectiveStage(base, override)   // DEPTH: province < district < individual
```

| 기본(확대 수준) | 탐색 단계 | 결과 |
| --- | --- | --- |
| province | district | district |
| district | district | district |
| individual | district | **individual** |
| 아무거나 | individual | individual |

시군구 단계로 들어간 뒤 사용자가 개별 핀이 보일 만큼 더 확대했는데 다시 묶이면 확대가 먹히지 않는 것처럼 보인다.

### 해제 규칙

| 상황 | 처리 |
| --- | --- |
| 그 단계 안에서 확대·이동 | 유지 |
| **들어간 때보다 축소** | 해제 (`releasedByZoom`) — 상위 단계 탐색으로 돌아간 것으로 본다 |
| 전국 보기 / 모드 전환 | `resetStage()` |
| 필터 변경으로 핀이 바뀜 | `render()` 에서 해제 |

탐색 단계가 없으면 `clusterUnit(level)` 결과를 그대로 쓴다. **수동 확대·축소 동작은 이 기능이 생기기 전과 같다.**

## 4. 대표 좌표

군집 위치는 **묶인 주택 좌표의 산술 평균**이다(`regionCenter`).

추가 데이터 없이 현재 주택 데이터만으로 구할 수 있는 대신 필터가 바뀌면 위치가 조금 움직인다. MVP 에서는 이를 허용했다.
실제 화면에서 위치가 부자연스러우면 **`regionCenter` 하나만** 정적 행정구역 중심 좌표 조회로 바꾸면 된다.
`layoutPins` 가 좌표 계산 방식을 모르게 떼어 둔 이유다.

---

## 5. 같은 좌표 주택 묶기 (location grouping)

개별 핀 단계에서는 **좌표로 먼저 묶는다.** 같은 좌표에 여러 주택이 있으면 마커가 완전히 겹쳐
화면에서 하나처럼 보이고 클릭도 맨 위 하나만 닿는다. (실측: 316핀 → 255위치)

| 같은 좌표 주택 수 | 표시 |
| --- | --- |
| 1 | 일반 핀 |
| 2 이상 | **일반 핀과 같은 모양 + 우측 상단 숫자 배지** |

배지 핀을 행정구역 군집(둥근 알약)과 다른 모양으로 둔 이유는, 그것이 지역이 아니라 **지도 위 한 지점**이기 때문이다.

### 중복 제거는 보수적으로 한다

**서로 다른 공고의 주택은 절대 합치지 않는다.** 공고마다 별도 신청 기회이기 때문이다.
지문(`fingerprint`)이 `noticeId ⧉ title ⧉ address ⧉ rentalType ⧉ status` 로 **모두 같을 때만** 하나로 보여 준다.

- 판단 근거가 없으면(`noticeId` 없음, 주소 빈 값) 합치지 않는다 — `cannotCompare`
- 대표는 `housingId` 최솟값이다(입력 순서와 무관하게 결정적)
- 숨긴 것은 버리지 않고 `merged` 에 남긴다. `?housing=` 로 직접 들어온 주택이 숨겨진 쪽이어도 위치 강조가 동작해야 한다
- **불변식: `pins + merged = 입력`**

원칙은 `잘못된 병합 < 중복 표시` 다. 같은 공고·같은 좌표인데 주소 문자열만 다른 경우가 실제로 있어서
(`부천로470번길 70-1` / `부천로470번길 70-1 [구 570-25]`) 현재 데이터에서는 합쳐지는 쌍이 0건이다. 의도한 결과다.

## 6. 선택과 탐색 맥락

```
위치 마커 클릭 → 우측에 "이 위치의 주택 N개" 목록
목록에서 카드 클릭 → 상세 (?housing=)
상세에서 뒤로 → 그 위치 목록으로 복귀   ← 지도로 튕기지 않는다
```

- 목록이 열려 있는 동안 그 위치 마커는 **빨간색으로 강조**된다. 상세로 들어가도 유지된다
  (주택 선택과 위치 선택은 생명주기가 다르다 — `highlight(housingId, locationHousingIds)`).
- **새 탐색을 시작하면 이전 선택을 비운다.** 행정구역 군집 클릭과 전국 보기가 여기에 해당한다
  (`onExploreStart` → 위치 목록 닫기 + `?housing=` 비우기). 들어간 적 없는 지역에
  이전 목록이 따라오면 안 된다.
- 같은 좌표에 공고가 여러 건이면 **무엇이 다른지**를 카드에 보여 준다. 종로구 5건은 주소·유형·상태가 모두 같고
  **공고일만 다르다**(SH 311428/310976/310629/310300/309883). 그래서 카드에 공고명·기관·공고일·마감일을 함께 쓴다.

## 7. 행정구역 값은 백엔드 것을 쓴다

**프론트엔드는 지역 문자열을 임의로 보정하지 않는다.** `서울` / `서울시` / `서울특별시` 같은 표기 차이는
백엔드 `RegionNormalizer` 가 **저장 시점에** 정리한다. 자세한 내용은 [`docs/region-normalization.md`](./region-normalization.md).

- 핀 응답(`MapHousingSummaryResponse`)에 `province` / `district` 가 들어 있다. 주소 문자열 파싱은 하지 않는다.
- 군집 key 는 백엔드가 쓰는 `"시도 시군구"` 형식(`Candidate.regionKey`)과 같은 표기다.
- `shortProvince()` 는 **표시 전용**이다. 그룹 key 와 저장된 값은 건드리지 않는다.

지역 값이 비어 있는 주택은 **개별 핀으로 남긴다.** 조용히 사라지면 안 된다.

## 8. 정합성 규칙

- **군집 숫자 = 고유 Housing 수.** 서버가 주택 단위로 내려 주므로 핀 배열 길이가 곧 주택 수다. 공급 호실 수로 세면 부풀어 오른다.
- **불변식: `clusters 의 핀 수 합 + loose 길이 = 입력 핀 수`.** 지역 정보가 없다고 주택이 사라지면 안 된다.
- 집계는 **프론트에서** 한다. 현재 규모(수백~천여 주택)에서는 비용이 무시할 만하다.
  주택이 수만 건이 되면 그때 서버 집계 엔드포인트를 검토한다. 지금 하면 과한 구조다.
- `filter-options` API 의 region count 를 **지도 군집 수 계산에 쓰지 않는다.** 모수가 다르다.
- 지도를 움직일 때 서버를 다시 부르지 않는다. 확대 수준은 `clustering.ts` 가 `zoom_changed` 로 직접 듣는다.
- 필터를 바꿀 때 중심·확대 수준을 건드리지 않는다. `fittedRef` 가 **첫 결과에서만** 전체를 맞춘다.
- 마커·오버레이를 교체할 때 이전 것을 반드시 `setMap(null)` 하고 리스너를 해제한다.
  CustomOverlay 의 DOM `click` 리스너는 `maps.event` 가 모르므로 직접 떼어야 한다.

### ⚠️ DOM 에 붙은 군집 수로 전체 데이터를 판단하지 말 것

카카오 `CustomOverlay` 는 **화면 밖이면 DOM 에서 빠진다**(viewport culling). `Marker` 는 빠지지 않는다.
그래서 전국 보기에서 `.map-cluster` 숫자 합이 315 로 보여도 실제 데이터는 316 이다
(제주 1곳이 고정 전국 뷰 바깥). **데이터 정합성은 API 응답과 `주택 N곳` 표시로 판단한다.**

## 9. 결정 기록

| 결정 | 이유 |
| --- | --- |
| 레벨 경계 11 / 7 | 실데이터로 맞춘 초기 튜닝값. 최종 정책이 아니며 상수 하나로 조정한다 |
| 대표 좌표 = 평균 | 추가 데이터 없이 가능. 정적 중심 좌표로 바꿀 자리를 `regionCenter` 하나로 떼어 뒀다 |
| 프론트 집계 | 현재 규모에서 서버 집계는 과하다 |
| `MIN_CLUSTER_SIZE = 1` | 지역이 탐색 단위라 1곳인 지역도 지역으로 보여야 한다 |
| 강제 `setLevel` 제거 | `fitBounds` 범위 보장이 깨져 주택이 화면 밖으로 밀려났다 |
| 탐색 단계를 화면 전체에 적용 | 지역별로 주면 한 화면에 시도 군집과 시군구 군집이 섞인다 |
| 보수적 중복 제거 | 잘못된 병합이 중복 표시보다 나쁘다 (다른 공고 = 다른 신청 기회) |
| `includeUnknown` 토글 제거 | 지도 조회는 이 옵션을 쓰지 않는다. 화면에 두면 동작하지 않는 스위치가 된다 |
